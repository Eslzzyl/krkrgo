# Graphics, Layers, and Text Porting Status

## Bitmap

The native adapter is `Services.bitmapNative` in [`bitmap_native.go`](../internal/runtime/bitmap_native.go). Current code uses bounded pure-Go 32bpp RGBA storage and supports synchronous and asynchronous storage-backed loads, pixel/alpha access, size/copy/independence operations, header metadata, and lifecycle invalidation. Saving supports PNG, BMP, and JPEG. `encodeBitmapBMP` writes 8-, 24-, and 32-bit BMP paths; JPEG uses Go's `image/jpeg` encoder and recognizes `jpg`, `jpgN`, `.jpg`, `.jpeg`, and `.jif` type names.
`jpg` and the extension aliases use quality 90; `jpgN` selects the suffix quality, with values clamped to 1–100 and zero/empty parsed quality falling back to 10. A `quality` metadata value overrides the mode and is clamped to 1–100. `Bitmap.getSaveOption` declares only the `quality` range (1–100, default 90). These describe quality-selection semantics, not byte-identical C++ codec output.

`Bitmap.loadAsync` decodes storage data on a background goroutine and posts a main-session `onLoaded(meta, async, error, message)` callback. Object finalization invalidates pending requests through a generation check.

Remaining limitations include constructor/load color-key transformation and C++ raw `buffer`/`bufferForWrite` pointers (`ErrUnsupportedDevice`). The Go JPEG encoder cannot honor C++ `subsampling`, `dct`, or `progressive` controls; explicitly supplying any of those metadata keys returns `ErrUnsupportedDevice`. Other non-PNG encoders beyond BMP and JPEG are not implemented by this source.

## ImageFunction

[`image_function_native.go`](../internal/runtime/image_function_native.go) exposes a bounded pure-Go subset: clipped rectangle operations, nearest-neighbor stretch, general affine-matrix transforms, axis-aligned point-mode affine operations, flips, gamma adjustment, grayscale, fill/color rectangles, box blur, and text/glyph drawing. Source/destination clipping and overlap-safe copies are implemented.

`ImageFunction.drawText(bitmap, font, x, y, text, color, ...)` rasterizes through the supplied native `Font`'s selected real `FontFace`. `drawGlyph` accepts a glyph tuple with a 256-level octet coverage mask and uses the Bitmap's current font metrics for its origin. Both support an optional clip rectangle, nonnegative opacity, and `dfAlpha`, `dfOpaque`, or `dfAddAlpha` blending through the existing pure-Go pixel blender.

Unsupported paths include non-nearest stretch/affine sampling, rotated point-mode transforms and text/glyph drawing, hda, additive-alpha gamma, mask drawing, text/glyph shadows, unsupported draw faces, negative alpha-face opacity, non-antialiased text rasterization, and glyph masks other than the 256-level grayscale form. Mutating operations return `void` instead of C++'s optional updated `Rect`, because the VM lacks a safe host-side native-instance constructor.

## Layer and window

[`layer_native.go`](../internal/runtime/layer_native.go) bridges a bounded tree/property/pixel/clip/fill/color/text/hit-test surface. New and resized layer images use the C++/Rust neutral pixel colors by layer type, including transparent-white defaults for ordinary layers and transparent-black defaults for additive families. Complete C++ `Layer` behavior is not present. `Effect` and `Filter` can be retained as state types, but compositor execution returns `ErrUnsupportedLayerType` (`../internal/runtime/compositor.go`).

Layer image-size properties and `setSizeToImageSize()` return `ErrInvalidLayer` when the layer has no image buffer.

`Layer.beginTransition("crossfade", withchildren, source, options)` implements the built-in crossfade provider for same-tree layers with matching image sizes and required `options.time`; `Layer.beginTransition("spin", ...)` implements the extNagano line-rotation provider with `time`, `type1`, `type2`, and `accel` options. Other provider names return an explicit unsupported-provider error. A supplied `options.callback` is sampled on transition updates (not at begin) as a transition-relative clock initialized at zero; without it, the host clock is used. `options.selfupdate:false` advances during `Session.AdvanceClock`, while `true` advances during frame composition. The compositor interpolates or nearest-neighbour transforms the main-layer image pixels; child images are not transformed. Completion or `stopTransition()` exchanges image data, position, and visibility; `withchildren:true` also exchanges subtrees, while `false` preserves children at their tree positions. Completion calls `onTransitionCompleted(dest, src)` with the original objects. Stopping an idle layer is harmless.
`Layer.beginTransition("universal", ...)` is also supported when given a rule image through `options.rule`; its grayscale values drive the reveal, and `options.vague` controls the transition edge width. Rule images load from project storage and may be resized to the layer dimensions. These providers remain a bounded transition surface rather than arbitrary C++ plugin coverage.
`Layer.loadImages(storage, key?)` reads through the session Storage, decodes PNG, JPEG (`.jpg`, `.jpeg`, `.jif`), GIF (first frame), BMP/DIB, TLG5, and the bounded TLG6 subset into the layer's tightly packed non-premultiplied RGBA image, updates image dimensions/clip bounds, and returns the image's available tag dictionary or `null`. An omitted key preserves decoded alpha; RGB, adaptive, palette-index, and matte keys use the bounded Go image/key paths. When present, the C++/Rust-compatible `_m` mask sidecar replaces the decoded alpha channel, and `_p` province sidecars are decoded and tiled to the main image dimensions. Missing storage preserves `assets.ErrNotFound`; malformed images preserve `assets.ErrMalformed`; unsupported extensions/codecs preserve `assets.ErrUnsupported`. JXR is recognized by the native graphic extension order but is unsupported because no Go decoder is present.

[`window_native.go`](../internal/runtime/window_native.go) connects runtime-owned `Window`/`WindowEx`-related state, geometry, monitor queries, and deterministic event registration. This describes runtime state, not every OS window service in C++.
`Session.Input` resolves inherited window handlers and dispatches mouse events to the foremost hit-tested layer using layer-local coordinates. It tracks enter/leave transitions and per-button release capture, respects `Layer.eventTransparent`, and provides no-op native mouse event methods as `super` targets for TJS overrides. This is the bounded script input path for graphical button layers, not full OS window-message parity.

`Layer.light(light, contrast)` adjusts clipped RGB channels, clamps transformed values to 0–255, and preserves alpha. The focused native behavior test verifies representative adjusted colors, clamping, alpha preservation, and transparent-pixel handling.

## Font and text rendering

[`font_native.go`](../internal/runtime/font_native.go), [`font.go`](../internal/runtime/font.go), and [`font_system.go`](../internal/runtime/font_system.go) provide explicit font selection, pure-Go system font discovery, and C++-style fallback. `FontBook` preserves explicit registrations and ordered comma candidates; `FontSystem` resolves a missing request through the configured default, explicit real faces, platform-known real families, and finally discovered system faces.
Family lookup applies Unicode NFKC normalization, case folding, and whitespace normalization (so full-width `ＭＳ` spelling matches normalized names) without registering synthetic aliases. A missing Japanese Mincho/serif request (including `ＭＳ Ｐ明朝`) tries ordered real serif families before generic Japanese sans families: Hiragino Mincho ProN on macOS, Noto Serif CJK JP on Linux, and MS PMincho on Windows, then the platform's remaining Japanese-capable candidates. Other missing Japanese requests retain their ordered platform candidates, including Hiragino Sans and Hiragino Kaku Gothic ProN on macOS. TTC collections are read face-by-face, retaining each valid real OpenType face and reporting unsupported faces without discarding other usable fonts.
For the lovelyday acceptance project on macOS, a request for MS P Mincho (`ＭＳ Ｐ明朝`) resolves through the real-family fallback to Hiragino Mincho ProN. The fallback selects an available face; it does not claim that the Japanese font metrics or glyph rasterization are identical to Windows MS P Mincho.
The scanner reads real TTF/OTF/TTC/OTC/dfont files from conventional Darwin, Linux, and Windows font directories and registers their family names through `golang.org/x/image/font/sfnt` and `opentype`. Discovered faces and `ParseOpenType` factories use 72-DPI pixel sizing and full TrueType hinting with grayscale antialiasing: this matches C++ `LayerBitmapImpl.cpp` setting `font.Hinting = true` and `FreeTypeFontRasterizer.cpp` retaining antialiasing while enabling hinting. The previous `HintingNone` left outlines unaligned to the pixel grid and made small text visibly softer. No font-name alias or synthetic glyph face is created. Each `Layer` lazily creates and retains a stable default `Font` object when its `font` property is first read; replacing the binding or invalidating the layer releases that layer-owned native Font state.
Runtime text is rasterized into the native layer/bitmap pixel grid with integer-origin baselines before the compositor copies those pixels to the frame. `host/ebiten.go` uploads that frame and Ebitengine presents its logical canvas; when the window/client dimensions do not match the logical frame, Ebitengine's presentation scaling can still soften or enlarge glyph edges. This remains a limitation; the host does not resample text separately. Custom registered `FontFace` values retain their own rasterization settings.

Native `Font` exposes `getTextWidth`, `getTextHeight`, and all four `getEscWidth/HeightX/Y` methods. Escapement components rotate measured text width and the absolute configured font height by `angle` in tenths of a degree, matching C++ `LayerBitmapImpl.cpp`/`LayerIntf.cpp`.
Measurement and rasterization require a real selected face. Ruby shaping, full vertical-font shaping, graphical-character parity, and complete C++ `TextRenderBase` behavior remain unsupported.

## C++ comparison

These bridges cover selected C++ APIs. Explicit errors preserve boundaries where Go cannot safely expose C++ pointers or where corresponding rendering behavior is not implemented.
